# docs

> **2026年8月にスコープを再定義しました。** 現行スコープは食材在庫管理・大人用献立提案・週間献立表の発展・ぴよログ連携です（`mealtracking_usecase_ui.md` 10章参照）。離乳食トラッキング機能（M1〜M3）は廃止し、`archive/mealtracking-m1-m3` ブランチに保全しています（詳細はリポジトリルートの `README.md` 参照）。

食材在庫管理・大人用献立提案・週間献立表・ぴよログ連携の開発方針・データモデル設計・実装計画をまとめたドキュメント群です。実装作業の前に該当ドキュメントを確認し、既存の設計判断・データモデル・命名規則との一貫性を保ってください。ブランチ運用など開発フロー全般のポリシーはリポジトリルートの `CLAUDE.md` を参照してください。

## ファイル一覧（現行スコープ）

- **`inventory_menu_usecase_ui.md`** — 食材在庫管理・大人用献立提案・ぴよログ連携のユースケース・画面構成・実装タスクリスト。進捗管理はこのファイルのチェックリストに一元化する
- **`inventory_menu_design.md`** — 現行スコープの技術設計・データモデル（`Food`（作り直し）／`Inventory`／`InventoryEvent`等）・Dexieスキーマ。4章に本リポジトリでの実装時の差分（実装メモ）を記載
- **`inventory_menu_claude_code_instructions.md`** — 現行スコープのClaude Code向け実装指示書（ステップ0〜6）。ステップ6（実データでのぴよログパース精度調整）は実データ提供待ちで未着手
- **`mealtracking_usecase_ui.md`** — 0〜9章は旧スコープ（離乳食トラッキング、M1〜M5）の経緯として保持。10章にスコープ再定義の経緯・方針を記載
- **`mealtracking_m1_design.md`** — 旧スコープM1・M1.5・M1.6の技術スタック・データモデル（`Food` / `MealRecord` 等）・Dexieスキーマ（経緯として保持）
- **`mealtracking_claude_code_instructions.md`** — 旧スコープM1系（ステップ0〜13）の実装指示書（経緯として保持、実装完了済み）
- **`mealtracking_m2_design.md`** — 旧スコープM2以降（M3：アレルギー・初回食材管理、M2：献立記録＋週間献立表）の技術設計。`MenuPlan`／`MenuLog`（予定・状態とイベントの分離）は現行スコープでも継続利用（経緯として保持）
- **`mealtracking_claude_code_instructions_m2.md`** — 旧スコープM2以降（ステップ14〜22）の実装指示書（経緯として保持）

## 運用ルール

- 実装中に設計との食い違いが出た場合は、コードだけでなく該当ドキュメント（現行スコープは `inventory_menu_design.md` / `inventory_menu_usecase_ui.md`）も更新してから次の作業に進む
- 各ステップ・タスク完了時は `inventory_menu_usecase_ui.md` の該当チェックリストにチェックを入れる
- 計画にない追加要望を実装した場合も、影響するデータモデル・ユースケースがあれば該当ドキュメントに追記する
- 旧スコープのドキュメント（`mealtracking_*`系）はそのまま残し、経緯・過去の設計判断の参照用として保持する（実装済みコードとして参照するものではない）
