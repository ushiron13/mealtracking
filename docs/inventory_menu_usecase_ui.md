## 1. ユースケース：食材在庫管理

### 1.1 食材マスタの管理方式（前提）

食材ごとに、登録時にどちらの管理方式で在庫を扱うかを選べる。

| 管理方式 | 対象イメージ | 入力形式 |
|---|---|---|
| 数量管理 | にんじん・じゃがいも等、個数で数えやすいもの | 個数・グラム等の具体的な数値 |
| 概略段階管理 | 調味料・冷凍食品等、正確に数えにくいもの | 多い／少ない／なし の3段階（M1で確立した完食度と同じ発想） |

### 1.2 UC1：食材在庫の新規登録
- トリガー：買い物後
- フロー：
  1. 食材を選択（食材マスタになければ新規追加。追加時に管理方式を選ぶ）
  2. 管理方式に応じて入力：数量管理なら個数・グラム等、概略段階管理なら初期段階（多い／少ない）
  3. 保存 → 既存在庫があれば加算（同じ食材の追加購入の場合）

### 1.3 UC2：食材の消費記録（在庫を減らす）
- トリガー：料理で使ったとき、またはぴよログ連携での自動反映時（UC6）
- フロー：
  - 数量管理の食材：「使い切った」ボタンで在庫を0にする（部分消費の数量入力はしない、入力負荷を優先して精密な残量計算はしない）
  - 概略段階管理の食材：段階を一つ下げるボタン操作（多い→少ない→なし）
- 性質：どちらも「今どのくらいあるか」の大まかな把握が目的。精密な数量計算はしない方針（`persona_usecase_mvp.md`の「三段階完食レベルが実用的」という原則を在庫管理にも適用）

### 1.4 UC3：在庫の確認
- トリガー：献立を考える前、買い物前
- フロー：在庫一覧を開く → 「なし」「少ない」の食材が視覚的に分かる（優先的に使うべき・買い足すべき食材の判断材料）

## 2. ユースケース：大人用献立提案

### 2.1 UC4：大人用献立提案の取得
- トリガー：利用者が能動的にアプリを開いて提案を求める（受動的トリガー、`persona_usecase_mvp.md` 2.3の方針を継承。能動的トリガーは将来拡張）
- フロー：
  1. 提案画面を開く
  2. 在庫の「なし」「少ない」食材を優先的に使う候補メニューが表示される
  3. 主菜・副菜のバランスを考慮した組み合わせで提示
- 提案ロジックの要素（`persona_usecase_mvp.md` 2.4を継承・具体化）：
  - 在庫優先：「なし・少ない」段階の食材を優先的に使う候補を上位に出す
  - 主菜・副菜バランス（簡易版）：`FoodCategory`（M1.6で定義した種類軸カテゴリを在庫管理側でも流用）のうち「肉・魚・豆」＝主菜系、「野菜・くだもの」＝副菜系として大まかに対応させ、両方を含む組み合わせを優先する。栄養素軸の精緻な計算は行わない（M1.6での「栄養素軸は不採用」という判断を踏襲）
  - 週間献立表（`MenuLog`）との重複回避：直近の実施記録と同じメニューを続けて提案しない

### 2.2 UC5：提案の採否とフィードバック
- 「これ作る」を選択：
  - 使用予定の食材が消費記録（UC2）に反映される
  - 週間献立表（`MenuLog`）に実施記録として追加される（旧M2のデータモデルをそのまま利用）
- 却下時の扱い：`persona_usecase_mvp.md` 2.6の原則を継承。却下理由そのものより「却下によって在庫の無駄が生まれるかどうか」を基準に、別候補の提示か軽い確認かを判断する

## 3. ユースケース：ぴよログ連携

### 3.1 UC6：ぴよログデータの週次インポート
- トリガー：週1回程度、任意のタイミングで利用者が実行
- フロー：
  1. ぴよログアプリの「記録の出力」機能でテキストエクスポートを行う（利用者の手動操作）
  2. 出力されたテキストを本アプリに読み込ませる（貼り付け、またはファイル選択）
  3. アプリがテキストをパースし、食事記録から食材名を抽出する
  4. 抽出した食材について、在庫を消費記録（UC2）として反映するかどうかを確認画面で選べる（誤認識・不要な項目を除外できるようにする）
  5. 確定すると、該当食材の在庫が更新される
- 位置づけ：リアルタイム同期ではなく、週次のバッチ処理。アレルギー確認等のリアルタイム性が必要な用途はぴよログ側に委ねる

## 4. 画面構成

### ① 在庫一覧画面
- 食材ごとに管理方式（数量／段階）に応じた残量表示
- 「なし」「少ない」の食材を視覚的に強調（色分け等）
- 食材タップで詳細編集（数量入力 or 段階変更）
- 新規食材の追加導線（管理方式の選択を含む）

### ② 献立提案画面
- 在庫状況をもとにした提案メニューを表示（主菜・副菜の組み合わせ）
- 「これ作る」ボタン：採用時にUC5の処理を実行
- 「他の提案を見る」ボタン：却下時の候補入れ替え

### ③ 週間献立表画面（旧M2から継続）
- 縦＝曜日、横＝食事タイミングの表形式（変更なし）
- 献立提案（UC4）から採用したメニューも、通常の実施記録と同様に`MenuLog`へ記録される

### ④ ぴよログ連携画面（新規）
- テキスト貼り付け／ファイル選択のインポート導線
- パース結果のプレビューと、在庫反映の要否を食材ごとに選べる確認画面
- インポート履歴（いつ、何件反映したか）の簡易表示
